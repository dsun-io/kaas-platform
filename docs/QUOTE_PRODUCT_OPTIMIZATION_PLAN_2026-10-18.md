## 0. 结论摘要

- 本方案覆盖 **22 项需求**：报价工作台 **14 项**（用户原始 13 条 + 补充的「结果视图」）
  + 产品页面 2 项 + 产品名称/HS 编码/单证 HS 展示 3 项 + 侧边栏 1 项
  + 包装费用 1 项 + 企业抬头/收款/公章 1 项。
- 调研中发现 **5 个既存缺陷/缺口**（不是新需求，但必须顺手修，否则新交互会放大它们）：
  1. **条款选择没进算价请求**：`terms-amortize.ts` 把 `quote_as` 固定写成模板默认值（CIF），
     工作台选的 FOB/CFR 只改了单头 `incoterm`，**算出来的价仍是 CIF**（客户会拿到错价）。
  2. **汇率方向标反**：引擎语义是「1 外币 = ? CNY」（`price_per_piece / fx_rate`），
     界面却写「1 CNY = ? 外币」；且自动带入的汇率**永远是 USD→CNY**，切 EUR/GBP 后仍用美元汇率。
  3. **Worker 新建询盘默认状态非法**：`InquiryCreate.status` 默认 `"inquiry"`，
     而询盘状态机合法值是 `open/quoted/won/lost`（orchestrator 侧写死 `open`）。
  4. **单产品视图已是死代码**：`ProductQuoteView` / `FreightPanel` 没有任何路由引用，
     其中同样有条款勾选框/币种/利润双输入 —— 留着必然与新实现漂移，建议删除（见 §7）。
  5. **企业抬头页存在但"找不到"且权限有缺口**：`/settings/company-profile` 已有
     英文抬头 / 银行 / SWIFT / PNG 公章；但 PUT 接口**没有角色校验**（任何登录账号可改），
     页面又被放在 `adminOnly` 的系统设置里，团队管理员看不到；且没有报价页入口。
- 产品包装目前**没有数据模型**：只有 `product_profiles.info.packing` 文本，无法按规格/高度
  自动算包装费（需求 20）。
- 需要新增 **4 处 schema**：`customers.abbr`、`cust_inquiries.inquiry_no`（唯一）、
  `product_cost_history` 表、`team_product_status` 表。
- 按 P0~P5 分 6 批实施（§6），每批都跑门禁 + 真数据验收。

## 2. 现状：报价工作台到底是什么

`/quotes` 一个工位四个 tab：

| tab | 组件 | 说明 |
|---|---|---|
| 产品报价 | `QuoteWorkbenchView` + `WorkbenchParamsCard` + `QuoteLineCard` + `QuoteSummaryCard` | **本方案主战场**：整单参数 + N 个产品行 → 逐行算价 → 汇总 → 存报价单 → 生成单证 |
| 批量报价 | `BulkImportPanel` | 表格导入 → 一次算完（与本方案共享币种/汇率/条款） |
| 报价记录 | `QuotationRecordsView` | 台账（含成本/利润列，仅 internal） |
| 定价数据 | `PricingDataManager` | **当前语义 = 成本价表**（产品属性 `raw_price` 等）；用户认为价格每日波动，此表不适用 → 改为成本历史 |

关键数据流：

```
WorkbenchParamsCard（整单参数）
   └─ SharedQuoteParams（币种/汇率/日期/税率/利润/条款费用）
        └─ QuoteLineCard（每行：产品/规格/件数/利润覆盖）
             └─ buildLineRequest（唯一请求构造） → /export-quote/calculate[-internal]
                  └─ buildLineItem（结果 → 报价单行项 + cost_breakdown）
QuoteSummaryCard（汇总 + 保存 + 生成单证）
```

**引擎口径**（`backend/orchestrator/app/services/export_quote/`）：

- `pricing.py`：价链 = 进项税 → 退税让利 → 印花税 → 销项税；`margin_on_price` 模式
  售价 = 成本 ÷ (1 − 利润率 − `misc_fee_rate`)，此时印花税项为 0、杂税已并入售价。
- `terms.py`：贸易术语阶梯逐档累加；费用项 mode：`per_shipment / per_weight_ton /
  per_weight_kg / per_piece / ratio_of_subtotal / insurance_of_cif`。
- 汇率：`price_per_piece_fx = price_per_piece / fx_rate` ⇒ **fx_rate = 1 报价币 = ? CNY**。

## 3. 报价工作台 13 项设计

### 3.1 询盘编号自动生成（需求 1）

**现状**：`cust_inquiries` 只有自增 id 与 `inquiry_seq`（该客户第几次询价），**没有编号**；
工作台「询盘编号」输入框实际是**手填询盘数字 id**，填错就挂错询盘。

**方案**

1. 数据：
   - `customers` 新增 `abbr`（TEXT，2-6 位大写字母，可空）。
   - `cust_inquiries` 新增 `inquiry_no`（TEXT，唯一，可空；存量数据不回填，新建才生成）。
2. 生成规则（共享内核新函数 `build_inquiry_no(country, abbr, now)`）：
   - 国家 = 客户 `country` 的 ISO2（`US/DE/AU…`；空则 `XX`）；
   - 客户缩写 = `customers.abbr`（优先）；空则用客户名中的拉丁字母词首（最多 3 位）；
     仍为空则 `C{customer_id}`；
   - 时间戳 = `yyyyMMddHHmmss`（本地时区）；
   - 冲突（同秒同客户缩写）→ 追加 `-2/-3` 重试（最多 5 次）。
   - 例：`US-ABC-20261018170900`。
3. 覆盖所有创建入口（两端 + 定时任务）：
   - orchestrator `POST /customers/{id}/inquiries`；
   - worker `add_inquiry`；
   - `lead_scan.py`（线索回复自动建询盘）、worker `chain.py`（线索转询盘）；
   - 顺手修 Worker `InquiryCreate.status` 默认非法值 `"inquiry"` → `"open"`。
4. API/序列化：`row_to_inquiry` 增加 `inquiry_no`；详情/列表/客户往来记录都可读。
5. 前端：
   - 客户档案编辑表单加「客户缩写」（自动建议 + 可改；用于编号）；
   - 客户详情「询盘」页签展示编号（替代 `询盘 #id`）；
   - 工作台「询盘编号」改为**只读展示**：从客户页/询盘跳转带入 `inquiry_no`；
     同时提供该客户询盘的下拉选择（按编号搜索），不再手填数字 id。

**验收**：新建询盘 → 编号符合格式；同秒连续创建不冲突；工作台挂接的询盘编号正确；
存量询盘显示 `id`（无编号）不报错。

### 3.2 税务档案两个输入框缩减（需求 2）

**现状**（`WorkbenchParamsCard`）：`税务档案` 下拉 + 常驻的 `客户税率档案名称` 输入框 + 存为档案按钮，
占两个栅格、视觉臃肿。

**方案**

- 只保留一个「税务档案」下拉（客户档案 + 法定档案两层不变）。
- 「存为档案」改成下拉右侧的小按钮：点开才出现一行紧凑输入（名称 + 保存/取消），
  与单产品视图 `ProductTaxSection` 的既有模式一致；保存后自动选中新档案。
- 「移除该档案」保持为选中客户档案时的小字操作。
- 不改后端契约（quote-profiles 不动）。

**验收**：默认界面只有一个税务档案控件；存档案流程不超过两次点击。

### 3.3 去掉「启用出口费用」勾选，条款直选、默认 EXW（需求 3 + 8）

**现状**：`termsEnabled` 勾选框控制是否出现条款下拉与**全部 5 个费用输入框**；
报价请求的 `terms.quote_as` 永远取模板默认 CIF（Bug 见 §0）。

**方案**

1. 删除勾选框；条款下拉**始终显示**，默认 `EXW`。
2. 费用输入框按所选条款**只显示本档及之前各档累计的费用项**：
   - `EXW`：无输入；
   - `FOB`：国内费用（本地费用）；
   - `CFR`：国内费用 + 海运费（+ 海运费有效期，见 3.7）；
   - `CIF`：+ 保险费；
   - `DAP`：+ 目的港费用及送货到门；
   - `DDP`：+ 进口关税及税费。
3. 请求构造：
   - `terms.quote_as = 所选条款`；
   - `terms.ladder` **截断到所选档**（引擎不再计算更高档，避免"没填运费却出现 CIF 价"的误导）；
   - 未显示的项不发送/值为 0。
4. 模板 `DEFAULT_EXPORT_TERMS.quote_as` 从 `CIF` 改为 `EXW`（用户要求默认 EXW），
   同步 `frontend/src/mocks/export-quote-data.ts`、文档与测试。
5. 单头 `incoterm = 所选条款`（含 EXW），与算价口径一致。

**验收**：默认 EXW 且无费用输入；选 CFR 只出现国内费用 + 海运费；

### 3.9 利润只留百分比 + 金额小字回显（需求 9）

### 3.10 印花税 → 杂税（需求 10）

**现状**：界面有「印花税率（%）」+「印花税计税基数」；但用户确认的口径是
**一个 3% 的综合杂税**（引擎 `misc_fee_rate`，产品定义里已有 `misc_fee_rate: 0.03`）。
当前 margin 模式下印花税本来就被置 0、杂税并入售价分母 —— 界面上的印花税字段是**误导**。

**方案**

- 删除界面的「印花税率」「印花税计税基数」；替换为单个「杂税率（%）」：
  - 默认值取产品定义的 `misc_fee_rate`（现为 3%），可本单覆盖；
  - 下发 `policy.misc_fee_rate = 百分比 / 100`；
  - **不再下发** `stamp_rate/stamp_base`（旧字段保留在 API/引擎，供历史 fixed/ratio 单复算）。
- 内部核算表：把「印花税」列改名为「杂税」，金额 = 不含税售价 × 杂税率（展示用，
  不改价链）；fixed/ratio 旧单仍显示原印花税值。
- 客户税率档案：新增 `misc_fee_rate` 保存/套用（后端白名单加一项）；
  旧的 `stamp_rate/stamp_base` 不再写入新档案，读取时忽略（不迁移，避免语义混淆）。
- 文案统一：杂税 = 除销项增值税外的杂七杂八税费总和，按售价计征。

**验收**：报价参数只有一个「杂税率（%）」；默认 3%；售价公式与用户示例一致；
内部表列名为「杂税」。

  （产品档案本来就是租户级）。
- 报价行项/单证读取顺序：行项 `spec_snapshot.hs_code`（已有）→ 产品档案 `info.hs_code`
  → 产品定义 `hs_codes[0]`。

**验收**：产品页可保存 HS；重新加载仍在；新报价行项带出该 HS；单证显示同一值。

### 4.6 企业自定义包装费用项（需求 20）

**用户口径（2026-10-18 确认）**

- 包装费**按卷/件**计；
- 配置在**产品管理**里：同一产品可有多条「包装方式」（包装1/包装2…），
  每条填写包装方式说明 + 收取金额（或收费区间，如高度 <2m 收 1 元、≥2m 收 2 元）；
- 每条报价**每个产品只采用一种包装**；可设某条为**默认包装**（未设置时取最早创建的一条；
  默认标识要显示在包装条目上）；
- 报价页根据当前规格条件**自动读取**对应包装的金额；
- 包装费**计入成本**（先加成本，再按 `成本/(1−利润率−杂税)` 算售价）。

**数据模型**

`ProductSpec`（产品定义 JSONB，现有 `spec` 字段）新增 `packaging` 数组：

```jsonc
"packaging": [
  {
    "id": "pack_1",              // 稳定 id（quote item 记录选择）
    "name": "标准包装",           // 包装1
    "method": "编织袋 + 钢带",     // 包装方式说明
    "is_default": true,          // 默认包装（同一产品最多一个；可切换）
    "created_at": "2026-10-18...",// 未设默认时按最早创建取默认
    "mode": "per_piece",         // 按卷/件
    "amount": 1.0,               // 默认金额（元/卷）
    "ranges": [                  // 可选：按规格属性分档（同时命中多条报配置冲突）
      { "field": "height_m", "min": 0, "max": 2, "amount": 1.0 },
      { "field": "height_m", "min": 2, "max": null, "amount": 2.0 }
    ]
  }
]
```

- 系统级产品：`packaging` 由平台定义（可空）；租户产品：产品定义页可视化编辑
  （不走裸 JSON，提供「包装1/包装2 + 默认 + 条件区间」表单，底层仍写 spec JSONB）。
- `spec_delta` 白名单补 `packaging`（团队覆盖系统产品时可用）。

**算价链路**

- 请求新增（每行）：`packaging_id`（缺省 = 该产品默认包装）；
- 引擎 `build()`：按 `packaging_id`/默认包装，用当前规格行解析 `ranges`
  （区间左闭右开；未命中用 `amount`），得到每卷包装费；
- 包装费**计入税前成本**（`cost = 材料成本 + 包装费/件`）后再走利润/杂税/价链；
- 响应 `cost_breakdown` 增加 `packaging_fee_per_piece` 与包装名，便于内部核算核对；
- 报价行项 `spec_snapshot` 记录 `packaging_id/name/fee`（历史单可追溯）。

**前端**

- 合并后的产品页「定义」区块：包装列表（名称/方式/金额/区间/默认标识）增删改；
  默认包装显示 Badge「默认」，切换默认按钮；未设默认时自动把最早创建的标为默认。
- 报价行：增加「包装方式」选择（默认预选默认包装，整单/行级可改），旁边小字显示
  「自动读取：¥1.00/卷（高度 1.8m）」，换规格/换包装即时重算；
- 单证：包装方式可并入现有 `specification` 或新增行项备注（不新增列，避免列过多）；
  至少保证内部核算与报价行能看到。
- 批量导入：模板增加可选 `packaging_id` 列；缺省用默认包装。

**验收**：产品可配多条包装并设默认（默认标识可见）；报价行按规格自动取金额；
成本含包装费后再算利润；换包装/换规格金额随之变化；保存后历史报价快照可追溯。

### 4.7 企业抬头 / 收款信息 / PNG 公章（需求 21）

**现状（几乎已实现，但入口与权限有缺口）**

- 页面：`frontend/src/app/(app)/settings/company-profile/page.tsx`
  —— **位置：系统设置 → 企业信息**（`/settings/company-profile`）。
  已含：英文/中文公司名、中英文地址、电话、邮箱、网站、
  银行名 / 银行账号 / **SWIFT Code**、默认付款条款；
  下方 `CompanySealCard` 已支持上传 **PNG 公章**、设默认章、删除。
- 缺口：
  - `PUT /tenant/company-profile` **没有角色校验**（任何登录账号都能改企业抬头）；
  - 公章接口只要求 `account_type=internal`，不是「团队管理员」；
  - 页面挂在 `adminOnly` 的系统设置组里 ⇒ **团队管理员（customer 账号）看不到**，
    用户反馈"我怎么没有看到"就是这个原因；
  - 报价页没有入口，业务不知道去这里维护。

**方案**

1. 权限（用户要求：只能团队管理员）：
   - 写：`is_team_admin(auth)` 才允许（company profile PUT、公章 POST/PUT/DELETE/默认章）；
   - 读：本团队成员可读（单据需要显示抬头/收款信息）；
   - 非团队管理员尝试写 → 403 `TEAM_ADMIN_REQUIRED`。
2. 入口：
   - 在报价工作台参数卡/整单汇总加「企业抬头与收款信息」链接（有权限才可点编辑）；
   - 设置导航增加「企业信息」项，按团队管理员可见（不要求 internal）；
   - 保留 `/settings/company-profile` 路径（旧链接不失效）。
3. 字段/校验：
   - SWIFT：8 或 11 位字母数字，保存前校验（单证审单会核对）；
   - 抬头完整性提示（缺英文名/银行/SWIFT 时在报价/单证页显示警告）；
   - 公章：仅 PNG（已有校验）、默认章唯一（已有）；
   - 付款信息：银行名/账号/SWIFT/默认付款条款（已有，补必填提示）。
4. 单证继承：现有 `seller_block()` 已把 company profile 映射到卖方区块、
   `apply_default_seal()` 已把默认公章注入单据 —— 保持唯一真源，不另写一份。
5. 回答用户"这个页面在哪"：`/settings/company-profile`（系统设置 → 企业信息），
   本地演示账号是 customer/owner，系统设置入口被 `adminOnly` 隐藏；
   本方案会把入口对团队管理员开放并在报价页给链接。

**验收**：团队管理员能进页面并保存抬头/银行/SWIFT/公章；非团队管理员只能看不能改；
新开单证自动带出抬头与默认章；SWIFT 非法时保存被拒。
