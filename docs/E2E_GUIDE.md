# 端到端测试说明书（一键可跑）

> 写给不懂代码的人：这份文档告诉你"端到端测试"是什么、怎么跑、跑完怎么读结果。

## 一、这是什么

"端到端测试"（e2e）= **模拟一个真人用户从头到尾用一遍系统**：自动打开网页 → 自动登录 → 自动铺好测试要用的数据 → 逐个页面点按钮、填表单、看结果对不对。

它回答的问题是："用户真的能把这件事用完吗？"——比单元测试（只验单个零件）更接近真实使用。

## 二、怎么跑（一键）

进入 `frontend` 目录，运行：

```
pnpm e2e
```

就这一条命令。它会自动完成：

1. **自动启动测试网站**（不用你手动起服务）；
2. **自动登录**（内置测试账号，不用你输密码）；
3. **自动铺数据**（每个测试自带假数据，不依赖你的真数据库）；
4. **逐个页面跑测试**，最后输出一张成绩单。

## 三、跑完怎么读结果

成绩单里的三种状态：

| 状态 | 意思 | 
|------|------|
| 通过 | 这个页面/功能真的能用 ✅ |
| 失败 | 这里有问题——要么是页面坏了，要么是测试本身写得不对（修复中） |
| 跳过 | 这个测试需要真实数据库等特殊条件，本机没有就先跳过 |

## 五、注意事项

1. **内存要够**：跑端到端要开浏览器，比较占内存。如果机器很卡（内存不足），测试会中途夭折——这时不是代码坏了，歇一会儿或关掉别的大程序再跑。
2. **代理软件干扰**：如果你开着 VPN/代理（如 Clash），测试可能连不上自己的网站。测试已内置自动排除本机地址；若仍连不上，试试暂时关掉代理。
3. **不用真数据库**：这套测试自带假数据，随便跑、随便中断，不会弄脏你的真数据。

## 六、常见问题

| 现象 | 原因 | 怎么办 |
|------|------|--------|
| 一上来全失败、提示"连接被拒绝" | 测试网站没起来 | 看命令输出开头的启动日志；或手动在 `frontend` 跑 `npm run dev` 后再试 |
| 中途报"内存不足/分配失败" | 机器内存不够 | 关掉别的大程序重跑；给 Node 多留内存（测试已内置 2GB 上限） |
| 某条标记"跳过" | 需要真实数据库/真实后端 | 属正常，本机没有相应条件 |
| 报价向导那几条红 | 页面与测试的历史不同步 | 归真修复中，见清理日志 |
