# 批量报价重设计 · 优化 Plan（2026-10-18）

> **用户方向（2026-10-18）**：现有「批量报价」价值不高；未来应设计成
> **同时选多个客户的多个询盘一起报价**。本轮税务档案改造**不动**现有批量页，
> 本文只出设计与任务拆解，等单笔报价稳定后再实施。

## 0. 现状

- 单笔报价：`/quotes?tab=product` 多产品工作台，按「一个询盘 → 多个产品行 → 一张报价单」。
- 现有「批量报价」：`BulkImportPanel`，本质是 **上传 CSV → 一次试算**，不落库、不建报价单。
- 缺点：
  - 与客户/询盘没有绑定，算完还要逐条手录；
  - 一个文件只能一套参数，不能按客户/询盘区分；
  - 结果无法直接进入客户往来记录，业务价值低。

## 1. 目标流程

**入口**：报价工位新增「批量报价」独立子页（替换现有 CSV 试算面板）。

1. **选客户（多选）**：左侧客户列表，可勾选多个客户。
2. **选询盘（多选）**：展开每个客户下的询盘（默认 `unquoted`，也允许 `quoted` 重新报价），
   勾选要报价的询盘；支持按状态/关键词筛选。
3. **批量填参数**：
   - 整批共享：币种、汇率、贸易条款、税务档案（按团队档案，自动填四税率）、利润率；
   - 按询盘覆盖：产品行、规格、数量、包装、成本、条款；
   - 每行实时算价，失败行标黄并给出原因，不阻塞其他行。
4. **生成报价单**：
   - **一个询盘生成一张报价单**（保持「询盘 → 报价单」业务链，不跨客户合并）；
   - 同一客户的多张报价单在结果里按客户分组；
   - 每张报价单自动取号（`QUO-国家-客户-时间戳`），询盘自动 `unquoted → quoted`；
   - 全部成功才提示完成；部分失败展示失败清单，可重试失败项。
5. **结果**：每行显示报价单号 / 客户 / 询盘号 / 总额 / 状态；可点开单张或导出汇总 CSV。

## 2. 关键口径

| 问题 | 结论 |
|---|---|
| 一张报价单覆盖几个询盘？ | **一个询盘一张报价单**；多客户不合并，避免客户归属/单证主体错乱。 |
| 多产品？ | 一个询盘可多产品行，复用单笔工作台行模型。 |
| 税务档案？ | 整批选一份团队档案，自动填四税率；允许按行覆盖，但**后端只按显式请求值算价**。 |
| 成本参考？ | 复用历史报价行项提取（同产品+同规格最近/30 天中位数）。 |
| 幂等/重复提交？ | 按 `(inquiry_id, quote 草稿)` 判重；同一询盘已有 draft 报价时默认更新而不是新建（可勾选“新建一张”）。 |
| 事务边界？ | 每个客户/询盘一组独立事务；单组失败不回滚其他组。 |
| 权限？ | 与单笔报价一致：客户可见范围 + 团队边界；管理员可跨团队但单据落客户团队。 |

## 3. API 设计（建议）

`POST /api/v1/quotes/batch`

```json
{
  "groups": [
    {
      "customer_id": 12,
      "inquiry_id": 34,
      "currency": "USD",
      "tax_archive_code": "CN-2026-09",
      "items": [{ "product_key": "chain_link", "spec": {}, "pieces": 100 }],
      "overrides": { "incoterm": "FOB", "profit_pct": 12 }
    }
  ]
}
```

返回：

```json
{
  "created": [{ "inquiry_id": 34, "quote_id": 90, "quote_no": "QUO-US-TIM-..." }],
  "failed":  [{ "inquiry_id": 35, "code": "SPEC_INVALID", "detail": "..." }]
}
```

- 复用现有算价引擎与服务端成本桥；不写第二套计算。
- 每组校验客户↔询盘归属；生成报价单后自动推进询盘状态。
- 解析/算价失败按组返回，不抛整批 500。

## 4. 前端拆解

- `BatchQuoteView`：三栏（客户/询盘选择 → 参数与行项 → 结果）。
- `BatchInquiryPicker`：客户多选 + 询盘勾选（显示询盘号、产品、状态）。
- `BatchParamsBar`：共享参数 + 税务档案 picker。
- `BatchLineTable`：按询盘分组，行内规格/数量/成本实时算价。
- `BatchResultPanel`：成功/失败分组、报价单号、重试失败项、导出。
- 不删除旧 `BulkImportPanel`，先并存；新页验收后再下线。

## 6. 风险

- **串单**：跨客户/询盘合并会导致报价单客户归属错乱 → 强制一询盘一单。
- **部分成功**：必须逐组事务 + 明确失败清单，不能整批回滚。
- **税务档案两个事实源**：档案只填前端值，后端仍只认请求显式税率。
- **性能**：批量行数大时 N+1；服务端批量算价 + 限制单批条数（建议 200 行）。
- **重复报价**：同询盘重复提交要先判重，避免同询盘多张草稿。
