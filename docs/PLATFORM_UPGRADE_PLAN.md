## 一、权威业务链（用户确认）

```
① 调研            市场调研（地区×产品×规格深化）
② 获客            地图源客户信息获取 + 客户触达
③ 客户 ★主线      询盘录入 → 建档 → 阶段跟踪 → 成交
④ 报价            ├─ 产品报价（产品本身价格：成本/利润/税/退税/贸易术语）
                  └─ 运输报价（货代运费：客户运费表 + 目的地 + 重量）
⑤ 单证            「正式报价」是本阶段的业务动作：向客户正式报价，
                  并继续按业务顺序产出各类单证（**工位名 = 单证**）
⑥ 订单            报价转化 → 履约 → 收款计划 / 应收
⑦ 出货            发运记录 → 回写情报（物流闭环）
```

**★ 客户是横向主线**：从询盘起沉淀，状态随业务推进（询盘 → 报价中 → 已报价 → 已成交 / 已流失），贯穿 ④~⑦。

**单证按业务顺序产出**（⑤ 内部）：
报价单 → 形式发票 PI → 销售合同 → 商业发票 CI → 装箱单 PL → 托运单/BL → 产地证 / 各类证书

> **术语纪律**：以上序列是**业务逻辑**表达，用于决定菜单**排序**；工位名与菜单项一律沿用**既有工位名**，
> **不照搬、不据此新造名称**。

## 三、侧边栏组织原则

> 用户给出的「调研 → 获客 → 报价 → 单证 → 订单 → 出货」是**业务逻辑顺序**，
> 用于决定菜单的**排列次序**，**不等于**菜单项清单：**不照搬、不据此造新名**。
> 菜单项一律沿用**既有工位名**（遵循 `WORKSTATION_DESIGN.md` §2.0 命名口径）。

**排列规则**
1. 主业务链（调研 → 获客 → 报价 → 单证 → 订单 → 出货）自上而下排列，体现业务推进
2. 支撑类工位（情报、数据）置于主链之后
3. **客户管理固定放在最下方、系统设置之前**（用户明确指定）
4. 管理类（设置 / 知识库 / 审计）置于最后
5. 每个工位**只有一个入口**；工位内部不自造二级侧边导航，必要处以 **跳转 / 嵌入 / 引用** 关联
6. 菜单必须与真实能力一致（无能力即摘除）
7. **侧边栏只放业务工位**；账号类入口（升级订阅）放**右上角头像**菜单

**目标形态（示意，P1 定稿）**

```
主业务链    调研 → 获客（含客户触达）→ 报价 → 单证 → 订单 → 出货
支撑       进出口情报、产品市场对照、报价数据
客户       客户管理          ← 固定位置（系统设置之前）
管理       系统设置（含 AI Providers）
右上角头像  升级订阅 / 账号
```

### P2 — 基座（设计语言 + 复用原语）

**设计语言方向（简约，参考 Claude 风格）**
- 去渐变、去彩色阴影；中性灰阶为主 + **一个**克制强调色
- 加大留白、统一圆角、统一边框层级；**排版优先**（字号/行高/字重形成清晰层级）
- 状态色仅在语义必要时出现；补齐语义色（成功/警告/信息/危险）**含暗色模式**
- 暗色模式完整可用（当前状态标签在暗色下**对比度不可读**）

**五个复用原语（覆盖全部页面）**

| 原语 | 解决什么 | 覆盖 |
|---|---|---|
| **页面骨架** | 标题/描述/操作区/内容区统一，权限守卫内建 | 21/21 页 |
| **数据表格** | 列定义驱动：三态、筛选、分页、对齐、截断、可选虚拟滚动 | 16 个文件 |
| **数据请求层** | 统一 `apiClient` + key 注册表 + 响应校验 + 三态出口 | 21/21 页 |
| **表单** | 统一表单原语：字段、校验、提交态、错误条、页脚；内联面板与弹窗规则统一 | ≥12 个表单 |
| **展示工具** | 金额/日期格式化 + 状态标签单一路径 + 状态字典集中 | 21/21 页 |

**顺带修复已确认的显示缺陷**
- 卡片裁切浮层（下拉被切）
- 删除确认弹层未走 Portal（脆弱，容器一变即错位）
- 筛选栏控件**不等高**（输入框与下拉高度不一致）
- 数字列未右对齐（金额/数量/评分左右混排）
- 空表格/空态有 **3 种**表现；加载态 **4 种**文案
- 长 ID（会话号/哈希）撑破详情面板
- 虚拟表格列宽与表头由两套算法决定 → **加列即错位**

**产出**：新设计变量 + 5 个原语 + 3 个样板页
**验收**：任选 3 页改造成样板并通过评审；暗色可读；无硬编码调色板（lint 强制）；控件等高、数字右对齐

### P4 — 工位（四个界面）

用 P2 原语实现，**只写业务配置，不重写表格/表单**：

| 工位 | 内容 | 关键联动 |
|---|---|---|
| **报价** | 产品报价（含批量导入、双视图：客户视图剔除成本利润 / 内部视图）+ 运输报价（运费表维护与试算）+ **报价记录**（历史台账视图） | 可一键生成「报价单」 |
| **单证** | 报价单 → PI → 合同 → CI → PL → 托运/BL → 证书，按业务顺序；含 18 类模板渲染与打印 | 引用报价/订单/询盘数据 |
| **订单** | 订单履约 + 收款计划 + 应收账款 | 可由「报价单」转化；向下触发出货与单证 |
| **出货** | 发运记录 | 回写情报，完成物流闭环 |

**业务规则**
- **报价记录台账加写入门槛**：仅在业务节点（报价单签发 / 订单成交）写入；**试算不落账**，避免垃圾流水
- 单证工位与报价工位为**交界**：报价工位管业务（客户/行项/汇率/状态），单证工位管成品（模板/渲染/打印），报价工位**调用**单证工位的渲染能力

**产出**：4 个工位页面 + 工位间跳转/引用
**验收**：每工位走完整业务闭环；**新增工位代码量显著下降**（量化对比）
