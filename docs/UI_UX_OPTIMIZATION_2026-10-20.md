## 0. 一页速览

**结论：现有界面“骨架能用、但不精致”，问题不在配色好不好看，而在信息层级、密度、一致性和反馈四件事。**

你截图里的两个直观感受是对的：

1. **左侧太重、右侧太空**：240px 深色侧栏 + 大面积渐变高亮，视觉重量全压在导航上；内容区（仪表盘/客户列表）信息密度极低，大量留白没有承担任何信息。
2. **“像没做完的后台”**：标题、Tab、状态标签、按钮、加载态、空态各有 2–3 套实现，同一类信息在不同页面长得不一样；用户需要重新学习每个页面。

**根因（均有代码证据，见 §1）**

| # | 根因 | 证据 |
|---|---|---|
| R1 | 组件没有真正“收编”：标题 2 套、Tab 3 套、状态标签 3 套、按钮 2 套 | §1.1 L1/L2、§1.4 C1、§附录 A.1 |
| R2 | 设计令牌存在但未被执行：渐变/阴影/硬编码语义色各行其是 | `.btn-brand` 定义 0 使用；硬编码 `text-red/green/amber` 28 处 |
| R3 | 列表页没有“列表结构”：客户管理仍是卡片堆叠，没有列、计数、空态引导 | `customers/page.tsx:1217-1259` |
| R4 | 反馈体系缺失：28 个文件用纯文本“加载中…”，表格无骨架、错误无定位 | §1.8 |
| R5 | 可访问性未进入验收：侧栏无 `aria-current`/焦点环，全站无 `prefers-reduced-motion` | §1.10 |

**本方案的做法**

- 不做推倒重来：保留 Next 16 + Tailwind + shadcn(base-ui) 与现有工位/路由/契约，**先收敛组件、再谈美化**；
- 视觉方向：**深色品牌侧栏降噪 + 浅色内容区提密度**；主色保留靛蓝，但“渐变只用于品牌时刻”，不再用于导航选中态和普通按钮；
- 分三期：P0 全局底座（令牌 + 布局壳 + 核心组件）→ P1 高频页面（客户/报价/仪表盘/情报/产品）→ P2 易用性与可访问性增强；
- 每项都给“改法 + 验收标准 + 是否纯前端”，并标注与现有 e2e 选择器的兼容约束。

**预期收益（可验收）**

| 指标 | 现状 | 目标 |
|---|---|---|
| 同类页面标题字号 | 24px / 30px / 36px 三种 | 1 种（22–24px） |
| 状态标签实现 | 3 套，同一“活跃”出现 2 种视觉 | 1 套 + 状态字典 |
| 首屏加载态 | 28 文件纯文本 | 100% 骨架/局部 loading |
| 列表页信息密度 | 客户列表 2 行占屏 60% | 表格化：同屏 ≥8 行 |
| 键盘可访问 | 侧栏/列表行不可聚焦 | 100% 可见焦点 + 行可键盘打开 |
| 1366×768 | 产品表 9 列横向溢出 | 无横向错位（次要列折叠/列宽策略） |
| 对比度 | 侧栏组标题约 3.3:1 | 正文/标签 ≥4.5:1，大字 ≥3:1 |

### 0.3 第三轮反馈：询盘链路与单证内嵌预览（2026-10-20）

**先回答三个事实问题**

| 问题 | 事实 |
|---|---|
| 一个报价单能有多个订单吗？ | 能。`orders.quote_id` 只有索引、没有唯一约束，`POST /orders` 也不拦；现实中“分批出货 / 同一报价重复下单”是合理场景，因此 UI 按真实数据支持 1:N，不强制 1:1（要强制需后端加约束，属业务改动） |
| 询盘和订单怎么挂？ | 不直接挂。`quote_orders.inquiry_id` 挂询盘，`orders.quote_id` 挂报价；一张询盘可有多张报价（改价重报），所以询盘 → 报价 → 订单是传递关系，订单没有 `inquiry_id` |
| 订单号和单证什么关系？ | `orders.order_no` 全局唯一；`trade_docs.order_id` 1 订单 : N 单证；单证也可只挂 `quote_id`（与 `order_id` 互斥）。多条订单时按订单分组，单条时扁平展示即可 |
| “上传的系统”有历史记录吗？ | 有**上传文件版本链**：`file_objects.version/is_current/supersedes_id` + `trade_doc_files` 角色 `render_pdf(_superseded)`，旧版不物理删；但**单证内容修改没有版本表**（draft 覆盖、issued 冻结），内容级版本需后端加表 |

**本轮落地**

- 列表：**询盘编号作主标题** + 阶段徽章；产品名降为副行且**只显示名称**（规格参数进详情）。去掉 CI/已签发等冗余 hint；不再显示“主要”标记。
- 阶段推导（展示层，不改后端 `cust_inquiries.status`）：**关闭 > 完结（订单 completed）> 发货（有 PL/BL 或订单 shipped）> 订单（有销售合同/CI 或存在订单）> 报价（有报价单）> 询盘**。
- 展开：产品 / 规格 / 联系人（只写名字，点击弹联系人信息弹窗）/ 渠道 / 数量 / 用途 / 创建时间；**删掉报价单+订单编号那一行**（不再重复）；单条订单直接扁平列单证，多条订单按订单分组；单证按生成时间倒序。
- 联系人：点名字弹出**联系人信息弹窗**（职位/电话/邮箱/WhatsApp），不跳页面、不写“主要”。
- 单证：点击**直接内嵌完整单据预览**（有单证工位权限时，复用 `DocPreview` + `/trade-docs/{id}/render-data`）；无权限显示说明；“在单证工位打开”降为次要入口；footer 重做为固定操作条（不再有负边距/灰条错位）。
- 历史留档：预览内展示**上传记录（PDF 版本链）**（当前/历史、vN、时间，点击打开原文件），数据来自现有 `GET /trade-docs/{id}/files`；内容级版本未做（需后端版本表）。
- 账号区：删除顶栏右侧的账号头像/下拉（与团队名重复且数据不足）；顶栏只保留团队名。侧栏底部新增**账号卡 + 「个人信息」弹窗**（账号类型/角色/团队/套餐，团队与工位、退出登录）。后端目前没有资料修改接口，弹窗明确标注“只读；修改资料请联系管理员”，不伪造编辑能力。
- mock：补 `render-data` 样板数据（让本地也能看到内嵌预览）、`files` 返回空；联系人种 3 位以演示排序。

证据：`docs/ui-redesign/phase4/*.png`（列表 / 展开 / 联系人弹窗 / 单证内嵌预览 / 账号区与个人信息）；`docs/ui-redesign/phase3/*.png` 保留上一轮。

### 0.4 签发后自动上传单证 PDF（2026-10-20）

- 业务口径统一叫**「上传单证」**，不再叫「归档」（内部文件角色仍是 `render_pdf` / `render_pdf_superseded`，不改表/接口）。
- Web UI 中**签发成功即自动上传单证**：`GET /trade-docs/{id}/render-data` → 前端 `renderTradeDoc` 生成 HTML → `POST /trade-docs/{id}/pdf`（服务端 Browser Rendering 出字节 → 既有落档链路：新版本上位、旧版挂 `render_pdf_superseded` 不物理删）。客户不再需要“打印另存 → 再导入一次”。
- **手动上传入口保留**：`POST /trade-docs/{id}/files/upload`（手动上传区）+ 单证工位「导入已有数据」；覆盖渲染器不可用、第三方签发单据、历史补档等特殊情况。
- **边界（如实记录）**：自动上传由 Web UI 在签发成功后触发；直接调用 API / 其他客户端签发不会自动出 PDF（HTML 模板在前端）。要服务端兜底，需要把渲染器搬到服务端或在签发接口接收 HTML，属跨栈改造，登记待办。
- mock：`POST /trade-docs/{id}/pdf` 返回 503（mock 无浏览器渲染器），前端如实提示“请手动上传”，不假装成功。
- 单元测试：`frontend/src/lib/trade-doc/__tests__/auto-archive.test.ts` 3 条（成功 / 503 / 404）。

### 2.4 主次操作位置（全站规则）

1. **页面级主操作**：PageHeader 右侧，主色按钮 1 个；次级操作 outline；破坏性操作不在页面头。
2. **板块级操作**：section 标题右侧，≤2 个。
3. **行级操作**：行尾 1 个主操作 + 「…」菜单；删除在菜单内且二次确认。
4. **表单**：右侧 sticky 摘要（计算 + 保存/签发）；窄屏底部 sticky 条。

### 2.5 表格列排列（列表页通用）

| 列类型 | 位置 | 规则 |
|---|---|---|

| 操作列 | 最右，固定 | 1 主操作 + 「…」；1366 下始终可见 |
| 低优先列 | 靠右 | 进「列配置」，默认隐藏（订单号/内部 ID 等） |

### 2.6 表单分组与排列

- 每张卡片 ≤3 组、每组 ≤9 个字段；组标题 15px + 一句 12px 说明；
- 桌面 3 列、1366 2 列、<1024 1 列；短字段（百分比/天数）可 2 列；
- 帮助文本默认 1 行（`line-clamp-1` + title），完整说明进 tooltip；必填 `*` 前置；
- 高级/低频参数收进「高级参数」折叠（仅布局折叠，字段与校验不变）；
- 右侧摘要 sticky，含计算值（现有字段）与主操作；错误字段滚动定位。

### 2.7 筛选区

- 单行：搜索（320px）+ 最多 3 个筛选 + 「查询/重置」；超过 4 个进「更多筛选」；
- 筛选控件高度 32/36，图标 + 文字；
- 已选条件用 tag 展示并可单删（纯前端状态）；
- 不新增需要后端支持的筛选维度（如跨表全文搜索）。

**状态语义字典**（跨页统一，tone 映射到 `StatusBadge`）

| 业务状态 | tone | 视觉 | 说明 |
|---|---|---|---|
| 活跃（客户阶段） | info | 淡蓝底 + 实心点 | “进行中”而非“成功” |
| 沉寂 | neutral | 灰底 + 空心点 | 与“停用”区分：停用更弱且带说明 |
| 已下单 | success | 绿底 + 实心点 | 业务结果 |
| 草稿 | neutral（描边） | 白底灰边 | 未生效 |
| 已签发 | success | 绿底 + 勾图标 | 不可再改的完成态 |
| 待处理/未报价 | warning | 橙底 + 警示图标 | 需关注 |
| 失败/已作废/已删除 | danger | 红底 + 图标 | 危险态 |
| 启用/停用（租户/账号） | success / neutral | 同上 | 与客户阶段区分文案 |

> 统一规则：**颜色 + 文案 + 图标/圆点**三者至少两个，禁止只靠颜色。

### 5.2 字号 / 行高 / 字重

| 用途 | 字号 | 行高 | 字重 |
|---|---|---|---|
| 页面标题 | 22 | 30 | 600 |
| 板块/卡片标题 | 15–16 | 24 | 600 |
| 正文/表格 | 14 | 22 | 400 |
| 标签/按钮/表单 | 13 | 21 | 500 |
| 辅助/说明 | 12 | 20 | 400 |
| KPI 数值 | 28（系统卡 22–24） | 1.1 | 600，`tabular-nums` |
| 表格表头 | 12 | 20 | 600，`text-muted-foreground` |

- 中文不加大字距；英文/数字标题 `letter-spacing: -0.01em`；
- 最小字号 12px（10/11px 仅允许非文本场景）；
- 字体栈：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`，并在 `fontFamily.sans` 里引用 `var(--font-sans)`（现状见 S7：Inter 已加载但未生效）。

### 5.3 间距 / 圆角 / 阴影 / 控件高度

| 令牌 | 建议值 | 用途 |
|---|---|---|
| 间距梯度 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 | 全部间距必须落在梯度上 |
| `--radius` | 10px（卡片/弹层）、8px（控件）、999（标签） | 与现有一致，收敛使用 |
| 阴影 | 仅 1 档：`0 1px 2px rgba(16,24,40,.04), 0 1px 3px rgba(16,24,40,.06)` | 卡片默认；浮层用 `--shadow-md` |

### 6.1 表格 `Table`

| 状态 | 视觉 | 交互 |
|---|---|---|
| 默认 | 表头 40px 浅底 12px/600；行 52px；1px 分隔线；首列 600 | 行 hover 底色；点击行打开详情 |
| 加载 | 5–8 行骨架（与列同构） | 不阻塞页面其他区域 |

| 错误 | 行区域内错误块 + 重试按钮（复用 query refetch） | 保留筛选条件 |
| 选中/禁用 | 不实现批量；禁用行 50% + `aria-disabled` | — |
| 密度 | 44/52 切换 | 记住选择 |
| 列配置 | 现有列显隐 | 记住选择 |

验收：sticky 表头、金额右对齐、1366 无横向错位、键盘可达行操作。

### 6.2 筛选区 `FilterBar`

- 结构：搜索（左，带清除）＋ 筛选控件（≤3）＋「更多筛选」＋「查询/重置」；
- 控件 32px 高、label 外置或 `aria-label`；已选条件 tag；
- 不新增后端筛选维度；状态存 URL（前端）。

### 6.3 表单 `FormField`

- label 13px/500 + 必填 `*`（前置/红色）；**每个控件必须有 `id` + `<Label htmlFor>` 或 `aria-label`**；控件 36px；help 12px（默认 1 行）；
- 错误：红边 + 3px 红色 ring + 12px 错误文案 + `aria-invalid`/`aria-describedby`（`form-field.tsx` 已支持，页面须改用）；
- 只读：浅底 + 正常对比 + 「只读」标记；禁用：50% + 禁指针 + 原因 tooltip；
- 提交失败：滚动到首个错误 + focus；顶部摘要可点击跳转。

### 6.4 选择器 `Select`

- 36px 高，单选；占位符灰色；打开后 `role=listbox`/`option`（base-ui 已具备）；
- 长列表虚拟化沿用现有 `@tanstack/react-virtual`（不改数据源）。

### 6.5 状态标签 `StatusBadge`

- API 不变（`tone/dot/children`），新增状态字典映射（§5.1）；
- 高度 24、12px/500、圆角 999；dot 6px；
- 禁止页面自造 `.badge-*` 与 `Badge` 用于状态。

### 6.6 反馈：Toast / ConfirmDialog

- Toast：右上（header 下方 16px），成功 4s，错误常驻 + 重试；最多 3 条；
- ConfirmDialog：标题=动词+对象，正文=影响（不写技术细节），按钮「取消 / 危险动作」（危险色在右）；不增删确认步骤。

### 6.7 按钮 `Button`

- 变体：primary（实色靛蓝，无渐变）、outline、ghost、destructive；
- 尺寸：28/32/36；icon-only 必须有 `aria-label`；
- loading：spinner + 文案不变 + disabled + `aria-busy`；宽度锁定防跳动；
- 禁用：50% + `aria-disabled` + 原因 tooltip。

### 6.8 页头 `PageHeader`

- 统一标题 22px + 描述 13px + 右侧操作；
- 页面级唯一主操作；面包屑来自契约（不改）。

### 6.9 空态/骨架 `EmptyState` / `Skeleton`

- 空态三种文案：无数据（引导主操作）、无结果（清除筛选）、无权限（说明+返回，不显示灰按钮）；
- 骨架与真实结构同构，避免跳动。

### 6.10 抽屉 `DetailDrawer`

- 右侧 480/560px；标题 16、内容分组、底部操作条；
- 打开聚焦标题，关闭回焦触发元素；移动端全屏。
