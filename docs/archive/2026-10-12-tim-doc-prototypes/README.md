## 关键算法要点（实现时优先复用这几处）

1. **行高估算**：合并单元格不自动撑高 → `est_lines` 需 ①按显式 `\n` 分段 ②按合并区真实宽度
   ③中文全角按 2 字符宽；否则中文条款/多行地址会被下一行压住。
2. **分页预算**：`fitToWidth=1 + fitToHeight=0` 时横向 A4 单页可用约 **600pt**（含约 0.86 缩放）；
   超预算把**末尾 section 整块**下移，避免公章被劈开。
3. **公章锚定**：图片尺寸是 **px、行高是 pt**（×0.75）；锚点取**签章行上边线**；
   图片必须紧裁（去白底残渣），否则视觉上"贴不住线"。
4. **导出后自检**：xlsx 单元格文本去空白后必须**全部出现在 PDF 文本**中（能抓出遮挡/截断）；
   `page.get_images()` 每页图片数=1（能抓出公章跨页）。
5. **一致性矩阵**：数值单元格要补千分位/小数位变体再比对（否则 `2,826.49` 之类因格式差异假报错）；
   单价必须按汇率精算（曾把 `2.18/6.7029=0.3252` 抄成 `0.3253`，造成假警报）。
6. **公章处理顺序必须是「裁 → 缩放 → 过滤」**：若先过滤后缩放，LANCZOS 会把透明白底混进红字边缘，
   产出约 **24% 的半透明近白晕影**像素（肉眼几乎看不见但确实存在，实测旧版 46,571 个可见像素里 11,091 个不是红像素）。
   把过滤器放最后一步，可见像素才能 100% 是红像素。

## ⚠️ 敏感信息提示

- 脚本内**硬编码了真实业务常量**：卖方抬头与地址、税号、收款银行账号、SWIFT、
  客户邮箱、真实价格与金额。仓库若转为公开或对外共享，需先做脱敏。
