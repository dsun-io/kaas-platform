### 2.1 关键设计口径（接手先读）

1. **客户阶段 = 汇总视图，不是源头**
   - 源头是**每张订单的状态**（`pending/confirmed/producing/shipped/completed/cancelled`）；
   - 推导（`_recompute_customer_stage`）：
     - 有未取消订单且任一处于 `confirmed/producing/shipped/completed` ⇒ `won`（成交）；
     - 有未取消订单但都 `pending` ⇒ `quoted`（已报价，待确认/定金）；
     - 无有效订单：有报价 ⇒ `quoted`；有询盘 ⇒ `inquiry`；否则 `lead`；
     - 手动 `lost` / 自动 `inactive` 是终态，自动推导不覆盖；**手动改阶段保留为兜底**；
   - 触发点：建询盘、建报价、建订单、`POST /orders/{id}/status` 后重算；**收款不改客户阶段**。
2. **流失（lost）必须上传客户拒绝文件**：无文件 422 `REJECTION_FILE_REQUIRED`；
   文件不属于该客户 422 `INVALID_REJECTION_FILE`；文件 id 记进 `cust_stage_log.reason`。
3. **汇率**：报价工作台读 `/fx-rates/latest` 时自动刷新（免费源每日更新，6 小时缓存，失败降级缓存并标 `is_stale`）。要分钟级实时需接商业 API。
4. **Excel 模板**：Worker 无 openpyxl（C 扩展），xlsx **由前端生成**；线上**上传**仍只收 CSV（要闭环需放开 Worker 的 `_reject_spreadsheet`）。
5. **管理后台三个页面**（灰度发布、属性沉淀提案、仪表盘指标）当前无实际用途，代码保留不投入 —— 详见 `docs/PROBLEM_STATUS_2026-10-11.md` 对应章节。

### 3.1 提交纪律（本仓库强制）

仓库可能多任务并行。**不要 `git add -A` / 裸 `git commit`**；用私有 index 只提交自己的 hunk：

```powershell
$env:Path = "C:\Users\河北慷逊公司\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin;C:\Users\河北慷逊公司\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\pnpm\bin;" + $env:Path
$env:GIT_INDEX_FILE = "$env:TEMP\own-index"
git read-tree HEAD
git add -- <自己的路径…>
git commit -m "…"          # 注意 commitlint：subject 用中文或全小写
Remove-Item Env:GIT_INDEX_FILE
git add -- <同样路径…>      # 归位共享 index
git push origin main
```

### 3.2 部署

- 正常方式：**push 到 `main`** 即触发 `.github/workflows/deploy.yml`（`paths-ignore` 掉 `**.md / docs/** / .tools/**`）；
  内含「同步共享内核 → 前端静态导出 → wrangler 部署 → 冒烟」。
- 手动兜底 / 回滚：见 `DEPLOY.md §0.1`（`wrangler rollback`）与 §4.1（部署没跑起来的排查）。
- Worker 环境变量/绑定**只能在请求期读**（曾导致生产鉴权漏洞），不要在模块顶层读 binding。
- R2 绑定必须走 `request.scope["env"].FILES`（`from js import FILES` 在线上不可用，实测 ImportError）。

### 3.3 常用验证

```powershell
$tok = "<登录拿到的 JWT>"   # 不要写进仓库
Invoke-WebRequest -Uri "https://api.kaas.powervoy.com/health"
# 汇率（应返回 rate/source/open.er-api.com）
Invoke-WebRequest -Uri "https://api.kaas.powervoy.com/api/v1/fx-rates/latest" -Headers @{Authorization="Bearer $tok"}
# R2 自检（管理员；排查文件落点/错误）
Invoke-WebRequest -Uri "https://api.kaas.powervoy.com/api/v1/file-objects/_r2_debug?key=_debug/r2-test.txt" -Headers @{Authorization="Bearer $tok"}
```

> 说明：写后立刻 GET 客户/阶段可能读到约 60 秒旧值（Hyperdrive 查询缓存），刷新即可；要强一致需调 Hyperdrive 的 `caching`。

### 3.4 R2 踩坑（已修复，后续文件功能都会遇到）

1. Python Workers 的绑定不在 `js` 全局：`from js import FILES` → `ImportError`；**改从 `request.scope["env"].FILES` 取**；
2. `obj.arrayBuffer()` 在 Pyodide 返回 **memoryview**（没有 `.to_py()`），旧代码抛 AttributeError 被吞 → 文件读回 404；已抽 `_to_bytes()` 兼容；
3. 写 R2 用 `to_js(bytes)`（`Uint8Array.new(bytes)` 不可靠）。

## 6. 故障处理速查

- **部署没生效 / 长时间 queued**：先看 GitHub Actions run 的 `deploy` job；若 Worker 已更新但页面旧，检查前端 build 是否成功、assets 是否随 deploy 上传。
- **接口 500**：逻辑同 `customers` 500 的教训——线上代码是裸 SQL，**DB 的 NOT NULL/默认值必须显式写**；先查表约束再改代码。
- **汇率 503/500**：先调 `/fx-rates/_debug` 看真实异常；已知故障源：外部源不可用（应降级缓存）、`js.fetch` 传 options 会崩（已改最小参数）。
- **文件读不到（404 `FILE_BODY_NOT_FOUND`）**：调 `_r2_debug` 看 binding/put/get；注意 §3.4。
- **回滚**：`DEPLOY.md §0.1`（按版本回滚，无需重新构建）；迁移是前滚式，回滚代码前确认迁移兼容性。
