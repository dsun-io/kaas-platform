## 1. 五项缺陷：根因与修复

| # | 现象 | 根因（代码证据） | 本轮修复 | 验证 |
|---|---|---|---|---|
| 1 | 客户创建后不能删除 | 前端客户页**从来没有删除入口**；`DELETE /api/v1/customers/{id}` 两端后端本来就有（软删除） | 客户详情加「删除客户」（二次确认）；删除前检查开启中订单，**409 `OPEN_ORDERS_EXIST`** 并回订单清单 | 本地 API：有 confirmed 订单时 409、取消后 204；列表消失 |
| 2 | 新建客户刷新后消失 | **Cloudflare Hyperdrive 查询缓存**：默认 `max_age=60s` / `stale_while_revalidate=15s`，写后不失效。旧交接 §3.3 已记录「写后约 60 秒旧读」 | 代码侧无法关闭；**部署时**执行 `npx wrangler hyperdrive update <ID> --caching-disabled`（见 §7）。本地 Docker/Postgres 无此缓存 | 本地刷新后立即可见（已实测） |
| 3 | 客户信息创建后不能编辑 | Worker 侧其实有 `PATCH /customers/{id}`（`ws_crm_ext.py`），但**前端没有编辑入口** | 客户页加「编辑档案」表单（公司名/国家/地址/港口/信用等级/备注）；联系人加编辑/删除 | 本地 API：改名/地址生效；e2e：保存后详情回显 |
| 4 | 手动改客户阶段不生效 | Worker `_recompute_customer_stage()` + `_refresh_stale_customer_stages()` **在读列表时**按询盘/报价/订单重算并覆盖手动值（还有 30/90 天自动流失/沉寂） | **删除整套自动推导与时间兜底**；客户阶段改为读时按「开启中的订单」推导，手动活跃/沉寂不再被覆盖 | 本地 API：手动 inactive 保持；有订单时显示 ordered、关闭后回 inactive |
| 5 | 阶段改为 活跃 / 沉寂 / 已下单 | 旧模型六值（lead/inquiry/quoted/won/lost/inactive），且与单据阶段混在一起 | 客户阶段 = `active` / `inactive`（手动）+ `ordered`（推导）；「流失」归订单阶段，客户阶段删除 `lost`；30/90 天规则删除 | 单测 + 本地 API + e2e |

### 1.1 阶段判定（唯一口径）

- **开启中的订单** = `status ∈ {pending, confirmed, producing, shipped}`（用户确认：pending 也算）。
  `completed` / `cancelled` 视为关闭。
- `ordered` 由读时 SQL `EXISTS(SELECT 1 FROM orders ...)` 推导，**不落库**；
  `customers.stage` 只存手动值 `active` / `inactive`。
- 接口统一回 `stage`（展示值）与 `manual_stage`（手动值）两个字段。
- 询盘 `won/lost`、报价状态、订单状态**只影响单据自身**，不再联动客户阶段。
- 共享真源：`backend/kaas_common/workstation/customer_rules.py`
  （`OPEN_ORDER_STATUSES` / `derive_customer_stage` / `normalize_manual_stage` / `validate_manual_stage`）。

## 2. 业务口径：谁定的

**用户定的（2026-10-18 弹窗 / 对话）**

1. 客户阶段只有三种：**沉寂 / 活跃 / 已下单**。
2. 有开启中的订单 ⇒ 已下单；开启中 = `pending/confirmed/producing/shipped`。
3. 沉寂**先手动切换**（不自动）。
4. 删除客户：**软删除**，且**有开启中订单时禁止删除**。
5. 订单阶段与客户阶段**严格分离**，不能混。
6. 「流失」属于订单阶段，客户阶段删掉流失。
7. 术语显示格式：`代码 · 中文（English）`。
8. 税费是 DDP 口径，**DAP 和 DDP 两个选项都要**。

**本轮自行决定的（工程细节，未改变业务结果）**

- 「已下单」**读时计算**而不是落库：避免出现「订单改了、客户阶段没跟上」的旧数据。
- 旧库值归一：`inactive/lost → inactive`，其余 → `active`；历史 `cust_stage_log` **不改写**（审计流水）。
- 删除接口返回 409 + 订单清单；前端展示可读原因。
- 编辑档案不包含阶段（阶段走专门端点），编辑表单不含联系人（联系人单独维护）。
- `termOptionLabel` 裁掉中文 label 尾部括号说明，保证只有一层括号（示例
  `DAP · 到门价（Delivered at Place）`）；说明信息在档位卡的费用项里。
- **默认对外报价术语仍是 CIF**（用户未要求改默认值）。
