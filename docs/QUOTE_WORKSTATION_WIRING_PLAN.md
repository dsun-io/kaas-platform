## 一、要解决的问题（现象 → 根因）

| # | 你看到的现象 | 根因（已实测验证） |
|---|---|---|
| 1 | 报价参数**属性不对** | 表单用的是**旧扁平规格模型**：缺「镀锌量」「工艺」两个**直接决定成本价格**的轴；多一个数据全空的「网孔规格」；「卷长」本应由丝径方案联动却让用户手选；选项里还混入了**另一套规格空间**（环扣），导致组合数 **65 ≠ 权威 48** |
| 2 | 点「获取报价」**永远失败** | 提交到一个**不存在的接口**；真正的算价接口在别处、从未被这个页面调用 |

| 4 | **很多接口 404** | 两侧后端各自演化，分三类（详见 §四） |

## 二、报价工位设计（P4）

### 2.1 信息架构：4 个平级视图，**取消嵌套**

| 视图 | 用户做什么 | 后端能力 | 现状 |
|---|---|---|---|
| **产品报价** | 选产品 → 选规格 → 填数量/汇率 → 算价 → 看双视图结果 | 报价引擎 | 引擎完备，**前端接错** |
| **批量报价** | 下载模板 → 填表 → 上传 → 预览 → 一次算完 | 报价引擎 | **已正确接线**（可作参照） |
| **运输报价** | 维护客户运费表 + 运费试算 | 运费计算器 | 后端写了一半，**缺接口与界面** |
| **报价记录** | 查看历史台账（只读） | 台账 | 有页面，口径待对齐 |

**评审要点**：去掉"页面套页面"，「定价数据」只保留一处（并入产品报价的内部视图，或独立成第五个视图 —— 见 §八 决策项①）。

### 2.2 产品报价的**属性口径**（本次核心）

**原则：不再让用户从"品类"里挑，而是从"引擎里真实存在、能算出价的产品"里挑；选中后属性由该产品自己的规格定义驱动。**

| | 牛栏网（唯一的真实产品） |
|---|---|
| 属性① | **网高**：1.2m / 1.5m |
| 属性② | **竖丝间距**：100mm / 150mm（对外表述为 10cm / 15cm） |
| 属性③ | **丝径方案**：全丝2.0 / 全丝2.5 / 边丝2.5+内丝2.0 |
| 属性④ | **镀锌量**：普锌40g/㎡ / 重镀锌≥200g/㎡ |
| 属性⑤ | **工艺**：无波款 / 波弯款 |
| 自动联动 | **卷长与卷径跟随丝径方案自动确定**，作为输入框的默认值带入，**可以改**（见 §2.5） |
| 组合数 | 2×2×3×2×2 = **48**（与引擎一致） |

**收益**：
- 消除"物理上不存在的组合"（原来可以拼出 高1.65m + 孔5cm + 卷长30m + 丝径1.8x1.8 这类工厂不做的规格）
- 补齐决定成本的两个关键轴（镀锌量、工艺）
- 属性名与业务口径一致（"网孔宽度"实为竖丝间距这类错名一并纠正）
- 产品清单天然只有能算价的产品（验证样本不会再漏到业务界面）

### 2.3 算价需要用户提供什么

| 输入 | 是否必填 | 说明 |
|---|---|---|
| 产品 + 5 个规格属性 | 必填 | 上面那套 |
| 按件参数（单件米数 / 卷径） | 可不填 | 默认跟随规格；填了则本单覆盖。两项**必须成对**：卷径决定体积（π/4 × 卷径² × 网高），是对外报运价/报关的口径 |
| 数量（件数） | 必填 | **不给默认值** —— 给一个默认件数，用户不填就直接提交，报出来的是他没确认过的数量 |
| **汇率** | 必填 | 引擎算外币价必需；建议**系统维护当期汇率、自动带入、可临时改**（见 §八 决策项②） |
| 法定税务档案 | 可留空 | 留空则自动取报价日当期生效的一份 |
| 客户税率档案 | 可不选 | 进项票税点 / 销项税率 / 出口退税率 / 印花税率 + 基数；**默认选最新存的一份**（见 §2.6） |
| 加工利润 | 必填 | 0 也拦住 —— 否则「忘了填」会静默出一张不含利润的价。金额与利润率**双向联动** |
| 让利比例 / 印花税覆盖 | 可不填 | 留空 = 用档案里的法定值 |
| 报价日期 / 有效期 | 有默认 | 默认今天 / 7 天 |

### 2.4 结果双视图

- **客户视图**：只有规格、重量体积、外币价 —— **不含成本与利润**，因此可以安全地直接给客户看
- **内部视图**：含成本、利润、税额、退税推导（需管理员权限）
- 引擎还会回**提示语**（如"退税率未核实"），前端要展示出来让业务确认，而不是吞掉

### 2.5 参数分区与显示口径（2026-09-27 实现为准）

页面按**计算顺序**分五段，每段一个带序号的标题：

| 段 | 内容 |
|---|---|
| 报价条件 | 产品、税务档案（法定 + 客户两层） |
| ① 规格 | 规格下拉（网高 / 竖丝间距 / 丝径方案 / 镀锌量 / 工艺） |
| ② 数量 | **单件米数 → 卷径** → 件数 → 总数（只读）。总额 = 单件数量 × 件数 |
| ③ 成本与利润 | 成本来自定价数据（随规格变）；加工利润金额与利润率双向联动 |
| ④ 税务与费用 | 进项票税点 / 销项税率 / 出口退税率 / 印花税 / 让利比例 |
| ⑤ 报价条件 | 币种、报价日期、有效期、汇率 |

**两处明确的设计选择**（都是为了避免「静默算错」）：

- **卷径放在「单件米数」后面**，不另起一段。两者是同一卷东西的两个面
  （一个决定重量、一个决定体积），分开摆会让人以为卷径是订单量。
- **单件米数与卷径必须成对维护**：卷径参与体积公式（π/4 × 卷径² × 网高），
  只改卷长不改卷径会把对外报运价/报关的体积算错。

**数值显示位数由产品定义声明、后端下发**（`Column.decimals` → 报价表里的 `decimals`
数组），界面只负责按位渲染：

| 列 | 位数 | 依据 |
|---|---|---|
| 单卷售价 / 总售价 / 报价（元/kg） | **2** | 参照表：「保留 2 位小数」 |
| 美元售价 / 总美元售价 | **4** | 参照表：「保留 4 位小数」 |
| 单价（元/米） | **4** | **不能压到 2 位** —— 参照表要求「单价 × 数量 = 总价，无四舍五入误差」。301.03 ÷ 100 = 3.0103，压成 3.01 后 ×100 = 301.00 ≠ 301.03 |
| 丝径（边丝 / 内横丝 / 竖丝） | **1** | 业务要求 |
| 其余列 | 不限定 | 如评分、系数本来就没有固定口径，硬套位数反而误导 |

两条纪律：

- 位数**写在产品定义里**（`export_quote/products/*.py` 的 `Column(decimals=…)`），
  界面不自己猜「金额该留几位」—— 两处实现就会两处不一致。
- **屏幕与导出（CSV）共用同一个格式化函数**。否则界面上 301.00、下载下来 301，
  用户会当成两个 bug 分别报。

### 2.6 客户税率档案（2026-09-27 新增）

**它是什么**：把「这个客户填过的那套税率」存成一份命名档案，下次一键套用。

- **只存税率类**：进项票税点 / 销项税率 / 出口退税率 / 印花税率 + 基数。
  **不含加工利润与让利比例** —— 那是每单的商业决策，被档案悄悄带回来会报出没确认过的价。
- **粒度：每个客户 + 每个产品一份**。不同产品的供货厂不同，进项票税点可能不同
  （牛栏网 10%、立柱 13%）。
- **可存多份、各起名字**；下拉里默认选**最新创建**的一份。
- **换了产品就换一列表**（粒度决定），未选时不套用任何档案，行为与之前一致。

**两条不可省的约束**：

1. 档案必须记住它当时绑定的**法定税务档案编号**（`rate_set_code`）。
   两层在同一个下拉里一起选，只套税率不切法定档案会拼出没人确认过的组合。
2. **切回法定档案时，表单税率项要恢复到默认值**，不能留着上一份档案的数字 ——
   否则用户以为「取消套用了」，实际还在用档案里的值。

接口与存储见 `docs/CURRENT_IMPLEMENTATION_MAP.md` §3.1。

## 三、报价记录台账的写入规则（P4 已定，务必遵守）

> **只在业务节点写入，试算不落账** —— 避免垃圾流水。

| 场景 | 是否写台账 |
|---|---|
| 单笔试算 / 批量试算 | **不写** |
| **报价单签发** | 写一条 |
| **订单成交** | 写一条 |

上一轮已按此实现「报价单签发 → 台账（整单一条）」，方向与 P4 一致 ✓

**同时明确**：「报价单」（有单号、汇率锁定、状态流转）按命名口径**归属「单证」工位**，不是报价工位的一部分；报价工位对它是"**一键生成**"的关系。

## 五、侧边栏与真实能力对齐

### 5.1 「系统设置」权限（**建议修正**）
现状：整个「管理」分组被标为"仅内部账号"，于是**客户方永远进不去系统设置**。
问题：客户方需要填写**本公司信息（公司名/地址/银行账号）**，这些**直接影响单证能否正确出具**。
建议：把「系统设置」中的**企业信息**对租户开放；平台级配置（AI Providers 等）仍限内部账号。

### 5.2 「市场调研」的契约不诚实
契约把它标为"已上线、正常可用"，但它的 5 个接口**两侧后端都没有** —— 内部账号点进去会满屏报错。必须二选一（§八 决策项③）。

### 5.3 一处命名重复
「勾花网」同时映射到两个内部代码，属于"不同事物用了一个名字"的隐性风险，建议收敛。

### 5.4 已确认无需改的
「定价数据」「产品市场对照」"已并入工位内部视图、不单占侧边栏"是**有意的**（符合规则 5「每个工位只有一个入口」），保留。

## 七、执行顺序（Wave）

| Wave | 内容 | 依赖 | 可独立验收 |
|---|---|---|---|
| **W1** | 报价工位信息架构重组（去嵌套、去重复入口） | 无 | 4 个视图各自可达、无嵌套 tab |

## 八、需要你决策的 3 件事

**① 「定价数据」放哪里？**
- (a) 并入产品报价的"内部数据"视图（推荐，符合"一工位一入口"）
- (b) 独立成第 5 个平级视图

**② 汇率从哪来？**
- (a) 系统维护当期汇率，报价时自动带入、可临时改（推荐，日常不用每次填）
- (b) 每次报价手工填

**③ 「市场调研」怎么办？**（它现在标着"已上线"，但后端两侧都没有）
- (a) **补后端实现**（前端页面已完成，补上后主业务链第一位就通了；工作量最大）
- (b) **先摘掉入口**（符合"菜单必须与真实能力一致"，诚实但业务链第一位空缺）
- (c) 先补**最小可用**（列表 + 统计能看），"从地图源挑选""深化"等动作排后续
