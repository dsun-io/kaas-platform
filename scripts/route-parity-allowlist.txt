# orchestrator / worker 路由对等 —— 允许「线上缺失」的路由清单
#
# 由来：orchestrator 与 worker 是两套代码，历史多次出现「本地有、线上 404」。
# 本文件是**棘轮**：只有登记在案的路由才允许缺失；一旦 worker 补上了，
# 对应行必须删掉（scripts/route-parity.py 会把过期登记判为失败）。
#
# 格式：METHOD /path   # 原因
#   · 原因里含「待补」= 承认这是**缺口**（不是故意不做）。脚本每次运行都会
#     把这些债单独打印出来，避免烂在文件里；补完后请删行。
#   · 原因不含「待补」= 线上**故意不做**（平台运维/本地运行时/依赖 Pyodide 跑不了的东西）。
#
# 证据与分类详见 docs/ROUTE_PARITY_2026-10-10.md
# 更新：python scripts/route-parity.py --update  （更新后必须人工复核原因）

# ── 平台运维 / 开发期治理：线上 Worker 不暴露 ───────────────────────────────
GET /api/v1/admin/deployment_audit  # 平台运维端点（内部部署专用），线上不暴露
GET /api/v1/admin/metrics/summary  # Prometheus 指标在本地运行时采集，线上不暴露
POST /api/v1/admin/cache/clear  # 本地运行时缓存运维端点
GET /api/v1/admin/tenants/{tenant_id}  # 平台运维端点，线上不暴露
GET /api/v1/admin/spec/attribute-proposals  # 属性沉淀提案：开发期治理功能
GET /api/v1/admin/spec/attribute-proposals/recommended  # 同上
PATCH /api/v1/admin/spec/attribute-proposals/{proposal_id}  # 同上

# ── 本地运行时探针 ──────────────────────────────────────────────────────────
GET /health/deep  # 深探针依赖本地进程/依赖检查，线上只需要 /health
GET /health/ready  # 同上

# ── 依赖 Pyodide 跑不了的东西 ───────────────────────────────────────────────
POST /api/v1/oss/presign  # 依赖阿里云 OSS SDK（C 扩展），Pyodide 装不了；前端有直传兜底
POST /api/v1/intel/collect/comtrade  # 采集任务由本地定时器调度，不在请求线程里跑

# ── 待补：前端未直接调用（能力差，按需补）──────────────────────────────────
GET /api/v1/product-specs  # 待补·规格清单（前端当前只在 mocks 里引用）
GET /api/v1/spec/attributes  # 待补·规格属性库
GET /api/v1/spec/attributes/search  # 待补·属性搜索
GET /api/v1/spec/attributes/{attribute_id}  # 待补·属性详情
POST /api/v1/spec/attributes  # 待补·属性创建
POST /api/v1/spec/attributes/{attribute_id}/values  # 待补·属性取值
GET /api/v1/spec/skus  # 待补·SKU 清单
GET /api/v1/spec/skus/{sku_id}  # 待补·SKU 详情
PATCH /api/v1/spec/skus/{sku_id}  # 待补·SKU 编辑
GET /api/v1/spec/templates  # 待补·模板清单
GET /api/v1/spec/templates/{template_id}  # 待补·模板详情
